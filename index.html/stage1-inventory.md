# LMS для сотрудников: инвентаризация функциональности

Корпоративная система обучения и адаптации сотрудников. Два клиента: приложение сотрудника (Telegram Mini App + веб-версия) и панель администратора. Бэкенд: REST API, PostgreSQL.

## Экраны

### Приложение сотрудника

| Экран | Что делает пользователь | Что происходит в системе | Роль |
|---|---|---|---|
| Главная | Видит сводку, жмёт «Продолжить» | Считается общий % по всем назначенным курсам и % адаптации, определяется следующий непройденный урок | сотрудник |
| Список курсов | Выбирает курс | Отдаются только активные назначения на опубликованные курсы. Для каждого курса вычисляется статус: не начат, в процессе или завершён | сотрудник |
| Курс (дни) | Открывает день курса | Проверяется, открыт ли день. День N+1 открывается, только когда все уроки дня N пройдены и наступила следующая полночь по МСК после последнего завершения. Открытый день остаётся открытым | сотрудник |
| День (уроки) | Выбирает урок | Отмечаются пройденные уроки, считается прогресс дня | сотрудник |
| Урок | Читает материал, смотрит видео, проходит тест, завершает урок | Разметка урока разбирается в блоки (карточки, шаги, заметки, сетки, видео). Позиция видео сохраняется каждые 5 с и восстанавливается. Кнопка «Завершить» заблокирована, пока тест не сдан. После завершения открывается следующий урок дня | сотрудник |
| Тест (внутри урока) | Отвечает на вопросы трёх типов: один вариант, несколько вариантов, свободный ответ | Сервер сам разбирает тест из урока и проверяет ответы, данным клиента не доверяет. Несколько вариантов засчитываются только при точном совпадении множества. Процент считается по автопроверяемым вопросам, проходной балл по умолчанию 80. Свободные ответы обязательны и уходят на ручную проверку. Не больше 10 попыток, после сдачи новые попытки не принимаются | сотрудник |
| Мои адаптации | Выбирает программу адаптации | % по каждой назначенной программе = пройденные блоки / все блоки | сотрудник |
| Программа адаптации | Идёт по дням, открывает блоки (время, цель, задачи, результат, ответственный, материалы) и отмечает выполнение | Блоки проходятся строго по порядку. Сервер проверяет, что пройденные блоки образуют непрерывное начало списка, и за один запрос принимает не больше одного нового блока | сотрудник |
| Таблицы | Открывает рабочие ссылки, добавляет, правит и удаляет свои | Корпоративные ссылки видны всем, личные только владельцу. Владелец проверяется на сервере | сотрудник |
| Профиль | Смотрит данные, меняет пароль для веб-входа | Пароль проверяется по правилам сложности и хранится в виде хеша | сотрудник |
| Вход на сайт | Логин и пароль | Access-токен + refresh в httpOnly-cookie, ограничение частоты попыток. В Telegram вход не нужен: подпись initData проверяется через HMAC | сотрудник |

### Панель администратора

| Экран | Что делает пользователь | Что происходит в системе | Роль |
|---|---|---|---|
| Главная | Быстрые действия | Переход к типовым сценариям | админ |
| Курсы | Создаёт курс, дни и уроки, пишет материал в markdown-редакторе с живым превью, загружает видео и вложения, меняет порядок перетаскиванием, публикует | Черновик не виден сотрудникам. Порядок дней и уроков сохраняется пакетно. Загружаемые файлы проверяются по типу и размеру | админ |
| Назначения | Назначает курс сразу нескольким сотрудникам, отзывает, удаляет | Массовое назначение (до 50 человек) выполняется в одной транзакции. Повторное назначение реактивирует отозванное, дубликатов не бывает. Неизвестные сотрудники отклоняются со списком ID. Отзыв мягкий, удалить можно только отозванное | админ |
| Адаптация | Импортирует программу из JSON, назначает, смотрит прогресс | Импорт нормализует и валидирует структуру: дни → блоки ↔ материалы. По каждому назначению считаются %, текущий день (первый с незакрытыми блоками), статус (в том числе «отозвано») и последняя активность | админ |
| Сотрудники | Ищет, выдаёт веб-логин и пароль, отключает доступ, скрывает из списка | Сотрудник появляется в системе автоматически при первом входе. Скрытие мягкое: при следующем входе сотрудник возвращается в список | админ |
| Результаты тестов | Фильтрует по сотруднику, курсу и статусу, раскрывает попытку, отмечает «Проверено», удаляет | Разбор по каждому вопросу: выбранные и правильные варианты, текст ответа. По умолчанию показываются непроверенные. Удалить можно только проверенную попытку | админ |
| Статистика | Смотрит сводку по курсам и по сотруднику, выгружает CSV | По курсу: сколько назначено, сколько завершили, средний %. По сотруднику: % по каждому курсу | админ |
| Таблицы | Управляет корпоративными ссылками | CRUD, активность, порядок | админ |

## Роли

- **Сотрудник** входит через Telegram (подпись initData проверяется, данные свежее 24 ч) или по логину и паролю. Видит только назначенное ему.
- **Администратор** входит по email и паролю (JWT). Управляет контентом, назначениями и проверкой тестов.
- «Ответственный» в блоке адаптации — просто текстовое поле, отдельной роли за ним нет.

## Структура данных

```
Course 1─* CourseDay 1─* Lesson          (урок может быть и вне дня)
Employee *─* Course      через Assignment (is_active, уникальная пара)
Employee *─* Lesson      через LessonProgress (завершён, дата, позиция видео)
Employee 1─* TestAttempt *─1 Lesson      (номер попытки, %, статус PASSED/FAILED/NEEDS_REVIEW/REVIEWED)
TestAttempt 1─* TestAnswer               (тип вопроса, выбранные/правильные, текст, верно/нет)
AdaptationProgram 1─* AdaptationDay 1─* AdaptationBlock *─* AdaptationMaterial
Employee *─* AdaptationProgram через AdaptationAssignment
Employee 1─* AdaptationProgress          (по блоку программы)
PortalTableLink                          (scope PERSONAL/CORPORATE, владелец)
Admin
```

## Нетривиальная логика

1. **Проверка знаний.** Тест описывается разметкой прямо в тексте урока, её разбирают и клиент (для отображения), и сервер (для проверки). Оценка серверная. Для вопросов с несколькими вариантами нужно точное совпадение множества. Процент считается только по автопроверяемым вопросам, проходной балл настраивается. Свободные ответы уходят на ручную проверку. Лимит — 10 попыток, после сдачи новые не принимаются.
2. **Завершение урока с условием.** Урок с тестом нельзя отметить пройденным без сданной попытки, это проверяет сервер (409).
3. **Подсчёт прогресса** на трёх уровнях: урок → курс (%, статус) → сотрудник (общий %). Плюс агрегаты по курсу: назначено, завершили, средний %.
4. **Ограничения доступа.** Любой запрос сотрудника проверяет активное назначение и публикацию курса. Если доступа нет, возвращается 404, а не 403, чтобы не раскрывать, что ресурс существует.
5. **Поэтапное открытие.** Следующий день курса открывается не раньше следующей календарной полуночи после завершения предыдущего.
6. **Последовательное прохождение адаптации** с серверной валидацией порядка и защитой от «перепрыгивания» через блоки.
7. **Жизненный цикл назначения:** назначено → отозвано → удалено, с реактивацией при повторном назначении. Массовые операции идут в транзакции.
8. **Процесс проверки тестов:** не проверено → проверено → удалено.
9. **Разметка контента** из собственных блоков (карточки, шаги, заметки, видео, тест) с живым превью в редакторе.
10. **Безопасность:** HMAC-проверка Telegram initData, ограничение частоты входа, пара access/refresh-токенов, хеширование паролей, валидация загружаемых файлов.

## Предложение: 4 экрана демо

| # | Экран | Какая инженерная работа видна |
|---|---|---|
| 1 | **Мои курсы**: карточки с прогрессом, фильтр по статусу, поиск; внутри курса дни с блокировкой | Статус и % считаются из прогресса по урокам, дни открываются по правилу, доступны только назначенные курсы |
| 2 | **Урок**: материал по шагам, тест, завершение | Проверка трёх типов вопросов, проходной балл, счётчик попыток, свободные ответы уходят на проверку, «Завершить» открывается только после сдачи, переход к следующему уроку |
| 3 | **Прогресс сотрудника**: курсы в работе и завершённые, %, даты | Пересчёт после действий на экранах 1–2, история попыток тестов |
| 4 | **Панель администратора**: сотрудники со сводкой, массовое назначение курса, результаты тестов | Назначение сразу появляется у сотрудника, отзыв и реактивация, разбор ответов, отметка «Проверено» |

Сквозной элемент: переключатель «Смотреть как: <сотрудник>» в шапке. Администратор назначает курс, переключается на сотрудника и видит курс у него.

Не входят: редактор курсов, адаптация, таблицы-ссылки, профиль, авторизация, CSV-экспорт.
